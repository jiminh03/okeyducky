# 기획 명세서

### 주제

1. **주제**
    
    부모의 마음으로 아이 곁을 지키는 AI 교감 메이트
    
2. **목표**
    1. 친근한 로봇을 통한 아이의 정서적 안정감 형성
    2. 실시간 아이 환경 모니터링으로 부모의 불안감을 해소하고, 심리적 안심을 확보
3. **이해 당사자 및 페르소나**
    1. **아이 (Primary User)**
        - **페르소나:** "호기심 많고 활발하지만, 때로는 부모님이 그리운 7~11세 아이"
        - **상황:** 맞벌이 부모님 때문에 혼자 있는 시간이 많은 아이. 유치원에서 속상했던 일이나 새로 생긴 작은 비밀처럼, 마음속에만 담아두기엔 너무 큰 이야기들을 털어놓을 상대가 없다. 신나게 자랑할 때뿐만 아니라, 속상하고 억울한 마음까지도 가만히 들어주고 고개를 끄덕여 줄 진정한 '말동무가 필요하다.
        - **핵심 니즈 (Needs):**
            - **정서적 안정감:** 혼자 있을 때의 무서움이나 외로움을 달래줄 존재.
        - **페인 포인트 (Pain Points):**
            - 혼자 노는 것에서 오는 **지루함과 외로움**.
            - 부모님이 보고 싶거나 무서운 생각이 들 때 느끼는 **분리불안**.
            - 자신의 이야기에 답해줄 상대방의 부재에서 오는 **답답함과 단절감**.
        - **기대 효과 (Gains from the Duck Robot):**
            - 말을 걸면 언제나 친근하게 반응해주는 **똑똑한 놀이 친구**가 생긴다.
            - 졸졸 따라다니는 오리 덕분에 혼자 있어도 든든하고, **부모님의 마음이 담긴 메시지를 오리의 친근한 목소리로 전달받으며** 안정감을 느낀다.
            - 오리와 대화하고 놀면서 **언어 능력과 사회성 발달**에 긍정적인 자극을 받는다.
    2. **부모 (Customer & Secondary User)**
        - **페르소나:** "아이와 함께하는 시간이 부족해 미안함과 불안감을 동시에 느끼는 워킹맘/대디"
        - **상황:** 직장이나 외부에서 업무를 보면서도 마음은 온통 집에 혼자 있을 아이에게 가 있다. 아이가 잘 있는지, 위험한 행동을 하지는 않는지, 외로워하지는 않는지 항상 걱정된다.
        - **핵심 니즈 (Needs):**
            - **아이의 안전 확인:** 실시간으로 아이가 안전한 환경에 있는지 확인하고 싶은 욕구.
            - **아이의 속마음 파악:** 아이의 표정 너머, 부모에게는 미처 털어놓지 않은 **숨겨진 생각이나 속상했던 일은 없는지** 더 깊이 알고 싶은 마음.
            - **원격 소통 수단:** 물리적으로 떨어져 있어도 아이와 연결되어 있다는 느낌을 받고 싶은 욕구.
        - **페인 포인트 (Pain Points):**
            - 아이 곁에 있어 주지 못하는 **미안함과, 지금 이 순간 아이가 무엇을 하고 있을지 알 수 없는 데서 오는 막연한 불안감**.
            - 근무 중에는 아이가 어떻게 지내는지 알 수 없는 **'깜깜이 육아'에서 오는 답답함**.
            - 바쁜 일상에 쫓겨 아이와 깊은 대화를 나눌 시간이 부족하고, 아이가 요즘 무슨 생각을 하는지(속마음), 무엇에 푹 빠져 있는지(관심사)를 놓치고 있다는 단절감.
        - **기대 효과 (Gains from the Duck Robot):**
            - 언제 어디서든 웹 서비스를 통해 스마트폰으로 아이의 모습을 보고 오리를 통해 메세지를 전달하면 **심리적 안도감**을 얻는다.
            - 대화 기록 리포트를 통해, 함께 있지 못해도 **아이의 대략적인 상태를 확인할 수 있다.**

### 핵심 기능

1. **교감 및 성장 기록 기능: "오리 친구의 오늘의 대화 리포트"**
    - **컨셉 (Refined)**
        
        부모가 궁금한 점을 대신 물어봐 주는 똑똑한 질문 메신저인 동시에, 아이의 혼잣말과 일상적인 이야기까지 귀담아듣는 든든한 **'비밀 친구'**! 이 두 가지 소통(질문에 대한 답변 + 자발적인 이야기)을 모두 기록하고 핵심만 요약하여, 부모가 아이의 하루와 생각의 **전체적인 그림**을 그릴 수 있도록 돕는 소통의 다리가 되어줍니다.
        
    - **세부 기능 (Revised):**
        - **① 핵심 대화 포착 및 기록 (STT 기술 활용):** 아이가 자신의 감정을 표현하거나(예: "나 이거 정말 좋아!"), 상상 속 이야기를 펼치거나, 하루 일과를 이야기하는 등 **의미 있는 순간의 대화를 선별적으로 포착**하여 텍스트로 기록해요.
        - **② 스마트 대화 리포트 생성:** LLM이 포착된 대화를 실시간으로 분석하여, 아이가 자주 사용한 **긍정적인 단어**나 부모가 알아두면 좋을 **특이사항**(예: '할머니 보고 싶다')이 발견될 때마다 '스마트 리포트'를 생성해요. 리포트는 주요 대화 주제를 간결하게 요약해주며, **요약의 근거가 된 원본 대화가 함께 페어링**되어 아이의 실제 표현과 뉘앙스까지 생생하게 전달해 줍니다.
            - *(예시)*
                - **요약:** "공룡 장난감에 큰 관심을 보였어요."
                - **원본 대화 보기 (펼치기):** "오리야, 오늘 민준이가 가져온 티라노사우루스 진짜 멋있었어. 나도 공룡 로봇 갖고 싶다... 엄청 큰 거!"
        - **③ 일일 리포트 정리 및 기록:** 하루 동안의 대화 분석 기록을 정리하여 일일 리포트를 제공해줍니다. 이를 통해 부모는 과거의 대화 내용을 확인하고 좀 더 세세한
            - *(예시) 특이사항: 오늘 '할머니 보고 싶다'는 표현을 3회 이상 언급했습니다.*
    - **기대 효과 (Revised):**
        - **부모:** 물리적으로 함께하지 못해도 아이의 하루와 주요 관심사를 놓치지 않고 파악하여 **유대감을 유지**할 수 있어요. 아이의 언어 습관이나 생각의 변화를 매일 확인할 수 있어 **성장 과정을 더 깊이 이해**하게 됩니다.
        - **아이:** 자신의 이야기에 항상 귀 기울여주고 기억해주는 오리에게 깊은 **신뢰와 정서적 안정감**을 느끼게 돼요.
2. **스마트 안심 케어 기능: "24시간 아이 곁을 지키는 수호천사 오리"** 
    - **컨셉:** 부모님이 잠시 자리를 비워도, 오리가 그림자처럼 아이 곁을 지키며 안전을 확인하고 즐거운 순간을 놓치지 않도록 도와줘요.
    - **세부 기능:**
        - **① AI 객체 인식 및 자율 주행:** 카메라가 아이의 모습을 인식하고, 아이가 움직이면 졸졸 따라다녀요.
        - **② 실시간 웹/앱 모니터링:** 부모는 언제 어디서든 스마트폰이나 PC로 아이의 모습을 실시간 영상으로 확인할 수 있어요.
    - **기대 효과:** 부모는 안심하고 외출할 수 있고, 아이는 혼자 있어도 졸졸 따라다니는 친구 덕분에 외로움을 덜 느껴요.
3. **원격 소통 및 조작 기능: "공간을 뛰어넘는 실시간 교감 채널"**
    - **컨셉 (Unchanged):**
    오리가 부모님의 아바타가 되어, 멀리서도 아이와 직접 소통하고 함께 놀아주는 신개념 원격 육아 도우미!
    - **세부 기능 (Revised):**
        - **① 듀얼 커뮤니케이션 모드:** 상황에 따라 오리의 소통 방식이 전환됩니다.
            - **(오리 모드):** 평소에는 귀여운 캐릭터 목소리로 아이의 말을 들어주고 간단한 상호작용을 하며 친한 친구 역할을 해요.
            - **(부모 모드 - 영상 통화):** 부모님이 앱을 통해 원격으로 접속하면, 오리가 움직이는 영상 전화기로 변신해요!
                - **실시간 영상 스트리밍:** 부모는 오리의 눈(카메라)을 통해 아이의 모습을 실시간으로 볼 수 있습니다.
                - **실시간 하이브리드 소통:** 부모가 앱에 텍스트를 입력하면, 오리가 즉시 그 내용을 **자신의 친근한 캐릭터 목소리로** 아이에게 전달합니다 (TTS). 반대로 아이의 목소리는 오리의 마이크를 통해 부모의 스마트폰으로 생생하게 들려 **실시간 대화**가 가능합니다.
    - **기대 효과 (Revised)**
        - **아이:** 부모님의 마음이 담긴 메시지를 **자신이 좋아하는 친구인 오리의 친근한 목소리로 실시간 전달받아**, 분리불안을 해소하고 강한 정서적 안정감을 느낄 수 있어요.
        - **부모:** 아이의 생생한 표정과 목소리를 직접 보고 들으며 교감하고, 원격 조종을 통해 놀이에 실시간으로 참여함으로써 **물리적 거리가 정서적 단절로 이어지지 않는** 새로운 방식의 유대감을 형성할 수 있습니다.

### 시나리오

1. **시나리오: 오늘의 대화 리포트**
    
    ```mermaid
    sequenceDiagram
        participant P as 부모 (Parent)
        participant C as 아이 (Child)
        participant D as 오리 로봇 (Device)
        participant S as 백엔드 서버
        participant LLM as LLM 분석 모델
        participant DB as 데이터베이스
    
        %% Part 1: 아이의 자발적 대화 포착 (비밀 친구 모드)
        Note over C, D: 아이가 혼자 놀며 오리에게 이야기함
        C->>D: "내 자동차 망가졌어... 너무 속상해."
        D->>S: 실시간 음성 데이터 전송
        S->>S: 음성을 텍스트로 변환 (STT)
        S->>LLM: 대화 내용 분석 요청 (감정, 키워드)
        LLM-->>S: '속상함' 감정 및 '장난감' 키워드 포착 (의미 있는 대화로 판단)
        S->>DB: 해당 대화 텍스트 저장
    
        %% Part 2: 부모의 질문과 아이의 답변 (질문 메신저 모드)
        Note over P, D: 부모가 앱으로 아이에게 질문을 보냄
        P->>S: 텍스트 질문 전송 ("저녁 뭐 먹고 싶어?")
        S->>D: TTS 변환 및 질문 명령 전송
        D-->>C: "저녁 뭐 먹고 싶어?" (오리 목소리로 질문)
        C->>D: "스파게티 먹고 싶어!" (대답)
        D->>S: 답변 음성 데이터 전송
        S->>S: 음성을 텍스트로 변환 (STT)
        S->>DB: 질문과 답변 쌍을 텍스트로 저장
    
        %% Part 3: 스마트 리포트 생성 및 전송
        Note over S, P: 의미있는 대화(특이사항)가 감지되었으므로 리포트 생성
        S->>S: 저장된 핵심 대화들로 '스마트 리포트' 조합
        S->>P: 앱 푸시 알림 전송 ("🐣 오리 친구가 새로운 소식을 가져왔어요!")
    
        %% Part 4: 부모의 리포트 확인
        Note over P, S: 부모가 앱을 통해 리포트 확인
        P->>S: 리포트 조회 요청
        S->>DB: 최신 리포트 데이터 요청
        DB-->>S: 요약 및 원본 데이터 반환
        S-->>P: 리포트 화면 데이터 전송
        P-->>P: 아이의 속마음과 답변을 함께 확인
    ```
    
    **[상황 설정: 각자의 공간, 연결된 마음]**
    
    - 오후 3시, 아이는 거실에서 혼자 놀고 있고 부모는 사무실에서 근무 중입니다.
    
    **[아이의 속마음 포착 (비밀 친구 모드)]**
    
    - 아이는 아끼던 자동차 장난감을 가지고 놀다 바퀴가 빠지자 시무룩해져서 옆에 있는 오리 로봇에게 속삭입니다. "내 자동차 망가졌어... 너무 속상해."
    - 서버는 이 대화에서 '망가졌어', '속상해' 같은 감정 표현을 **의미 있는 대화**로 판단하고, 해당 내용을 텍스트로 변환하여 기록합니다.
    
    **[부모의 궁금증 해결 (질문 메신저 모드)]**
    
    - 잠시 후, 부모는 저녁 메뉴를 고민하다 아이의 의견이 궁금해집니다. 스마트폰 앱을 열어 "오늘 저녁 뭐 먹고 싶어?"라고 텍스트를 입력하고 '오리에게 물어보기' 버튼을 누릅니다.
    - 거실에 있던 오리 로봇이 아이를 향해 부드럽게 움직이며, 자신의 친근한 캐릭터 목소리로 묻습니다. "OO아, 저녁 뭐 먹고 싶어?"
    - 아이는 오리의 질문에 "음... 스파게티 먹고 싶어\!"라고 신나게 대답하고, 이 답변 역시 서버에 즉시 기록됩니다.
    
    **[스마트 리포트 생성 및 확인]**
    
    - 아이의 감정 표현과 부모의 질문에 대한 답변이라는 **두 가지 특이사항이 포착**되었기 때문에, 시스템은 즉시 '스마트 리포트'를 생성하여 부모의 앱으로 알림을 보냅니다. "🐣 오리 친구가 새로운 소식을 가져왔어요\!"
    - 알림을 확인한 부모는 앱에서 다음과 같은 리포트를 확인합니다.
        - **주요 포인트:** 감정 표현 (속상함), 저녁 메뉴 요청
            - **요약 1:** 장난감이 망가져서 속상한 마음을 표현했어요.
            - **원본 대화 보기 (펼치기):** "내 자동차 망가졌어... 너무 속상해."
            - **요약 2:** 저녁 메뉴로 스파게티를 먹고 싶어 해요.
            - **원본 대화 보기 (펼치기):** "음... 스파게티 먹고 싶어!"
    - 리포트를 본 부모는 퇴근길에 스파게티 재료를 사 가기로 마음먹고, 집에 가서 아이의 장난감을 함께 고쳐주며 속상했던 마음을 위로해 줄 계획을 세웁니다.
2. **시나리오: 스마트 안심 케어**
    
    ```mermaid
    sequenceDiagram
        participant C as 아이 (Child)
        participant D as 오리 로봇 (Device)
        participant S as 백엔드 서버
        participant P as 부모 (Parent)
    
        %% Part 1: 자율 주행 및 상시 대기
        Note over C, D: 아이가 거실에서 놀다가 다른 방으로 이동
        C->>C: 놀다가 조용히 작은방으로 이동
        D->>D: AI 객체 인식으로 아이의 움직임 감지
        D-->>C: 아이를 따라 자율 주행으로 이동
        
        loop 지속적인 영상 스트리밍 준비
            D->>S: (연결 대기) 실시간 스트리밍 가능 상태 유지
        end
    
        %% Part 2: 부모의 원격 모니터링
        Note over P, S: 부모가 갑자기 아이가 조용해져서 걱정됨
        P->>S: 실시간 모니터링 요청 (앱 실행)
        S-->>P: 오리 로봇의 실시간 영상 스트림 연결
        P-->>P: 앱을 통해 아이가 안전하게 책 읽는 모습을 확인하고 안심함
        P->>S: 모니터링 종료
        S-->>P: 스트림 연결 해제
    ```
    
    **[상황 설정: 부모의 근무 시간]**
    
    - 오후 2시, 부모는 한창 업무에 집중하고 있고, 아이는 집에서 혼자 놀고 있습니다.
    
    **[AI 자율 주행 및 부모의 불안감 해소]**
    
    - 처음에는 거실에서 블록 놀이를 하며 쫑알거리던 아이가, 갑자기 조용해지더니 작은방으로 쏙 들어갑니다.
    - 오리 로봇은 아이의 움직임을 인식하고, 조용히 뒤를 따라 작은방으로 함께 이동합니다.
    - 사무실에 있던 부모는 갑작스러운 정적에 문득 '아이가 잘 있나? 혹시 어디 다쳤나?' 하는 걱정이 들어 스마트폰을 집어 듭니다.
    - 오리 로봇 앱의 '실시간 보기' 버튼을 누르자, 작은방 구석에 앉아 얌전히 그림책에 집중하고 있는 아이의 모습이 화면에 나타납니다.
    - 큰 소리로 아이를 부르거나 방해하지 않고도 아이가 안전하게 잘 있다는 것을 눈으로 직접 확인한 부모는, 막연한 불안감을 덜고 다시 편안한 마음으로 업무에 집중합니다.
3. **시나리오: 원격 소통 및 조작**
    
    ```mermaid
    sequenceDiagram
        participant P as 부모 (Parent)
        participant S as 백엔드 서버
        participant D as 오리 로봇 (Device)
        participant C as 아이 (Child)
    
        %% Part 1: 부모 모드 (영상 통화) 시작
        Note over P, S: 퇴근을 앞둔 부모가 아이와 소통하고 싶어짐
        P->>S: 앱에서 '영상 통화' 시작 요청
        S->>D: '부모 모드' 전환 신호 전송
        D->>D: 모드 전환 (e.g., LED 색상 변경, 알림음 발생)
        D-->>C: "띠링! 엄마에게서 연락이 왔어요!" (알림)
        S-->>P: 실시간 영상/음성 스트림 연결
        
        %% Part 2: 실시간 하이브리드 소통
        Note over P, C: 부모와 아이의 실시간 소통 시작
        P->>S: 텍스트 데이터 ("우리 OO이 뭐해요?") 전송
        S->>D: TTS 변환 및 재생 명령 전송
        D-->>C: "우리 OO이 뭐해요?" (오리 목소리로 재생)
        
        C->>D: 음성 데이터 ("나 그림 그려요!") 전송
        D->>S: 아이 음성 데이터 스트리밍
        S-->>P: 아이 목소리 실시간 재생
        
        %% (RC 조작 파트 삭제됨)
    
        %% Part 3: 부모 모드 종료
        P->>S: '통화 종료' 요청
        S->>D: '오리 모드' 복귀 신호 전송
        S-->>P: 스트림 연결 종료
        D->>D: 모드 복귀 (LED 색상 원복)
        D-->>C: "엄마랑 다음에 또 얘기하자!" (마무리 멘트)
    ```
    
    **[상황 설정: 퇴근 직전의 사무실]**
    
    - 오후 5시, 부모는 퇴근을 앞두고 집에 혼자 있을 아이가 눈에 밟혀, 잠깐이라도 소통하고 싶어집니다.
    
    **[하이브리드 소통 시작]**
    
    - 부모는 스마트폰에서 오리 로봇 앱을 열고 '영상 통화' 버튼을 누릅니다.
    - 집에 있던 오리 로봇의 눈 부분 LED가 부드러운 초록색으로 바뀌며 "띠링\! 엄마에게서 연락이 왔어요\!" 라는 귀여운 알림음과 멘트가 나옵니다.
    - 아이는 소리를 듣고 오리 로봇에게 다가갑니다. 부모는 앱 화면을 통해 아이의 모습을 실시간으로 확인합니다.
    - 부모는 앱 채팅창에 **텍스트로 입력합니다: "우리 아들, 뭐하고 있었어?"**
    - 잠시 후, 오리 로봇이 **자신의 친근한 캐릭터 목소리로** 엄마의 메시지를 그대로 읽어줍니다. "우리 아들, 뭐하고 있었어?"
    - 아이는 신이 나서 오리 로봇의 카메라를 보며 대답합니다. "엄마\! 나 오늘 새로 산 크레파스로 그림 그렸어\!" 아이의 생생한 목소리는 실시간으로 엄마의 스마트폰 스피커를 통해 들려옵니다.
    
    **[실시간 교감]**
    
    - 엄마는 아이의 그림을 더 자세히 보고 칭찬해주고 싶습니다. 앱에 **텍스트를 입력합니다: "우와, 정말? 그림 그린 거, 오리 카메라에 더 가까이 보여줄 수 있어?"**
    - 오리가 엄마의 메시지를 전달하자, 아이는 신이 나서 그림을 들고 오리 로봇의 카메라 앞으로 다가옵니다.
    - 부모는 앱 화면을 통해 아이의 그림을 자세히 보며 칭찬해줄 수 있습니다. 아이는 엄마의 칭찬을 실시간으로 들으며 기뻐합니다.
    
    **[소통 종료 및 일상 복귀]**
    
    - 몇 분간 아이와 즐거운 시간을 보낸 부모는 이제 퇴근 준비를 합니다. 마지막으로 **"이제 엄마 금방 갈게! 사랑해!" 라고 입력**합니다.
    - 오리가 따뜻한 목소리로 마지막 메시지를 전달한 후, 부모가 앱에서 '통화 종료' 버튼을 누릅니다.
    - 오리 로봇의 LED가 원래 색으로 돌아오고 캐릭터 목소리로 말합니다. "엄마랑 정말 재미있었지? 이제 곧 오실 거야\!"
    - 아이는 부모와 실시간으로 소통하며 분리불안을 해소하고, 부모는 아이의 세계에 직접 참여하며 안심하고 퇴근길에 오릅니다.
# 요구사항 명세서
## **기능적 요구사항 명세서 (시스템 요구사항 수정안)**

> 이 문서는 'AI 교감 메이트' 프로젝트가 수행해야 하는 기능적 요구사항을 정의합니다.
> 

### **1. 기능적 사용자 요구사항 (Functional User Requirements)**

> 사용자가 시스템을 통해 무엇을 할 수 있는지에 대한 상위 수준의 명세입니다.
> 
- **FR-U01: 공통 - 계정 및 로봇 관리**
    
    ⇒ 외동을 전제로 서비스를 구성, 두명 이상이 되면 음성 구분도 해야되서 매우 복잡해질듯
    
    > 부모 사용자가 서비스를 이용하기 위해 계정을 생성하고, 자신의 오리 로봇을 등록 및 관리하는 기능입니다.
    > 
    - **`FR-U01.1` (회원 가입):** 부모는 이메일 주소(ID), 비밀번호, **서비스를 이용할 단일 아동의 이름**(앱 내 호칭용) 등 최소한의 정보를 입력하여 회원 가입을 할 수 있다.
    - **`FR-U01.2` (로그인):** 부모는 가입 시 사용한 이메일 주소와 비밀번호를 통해 웹/앱 서비스에 로그인할 수 있다.
    - **`FR-U01.3` (로그아웃):** 부모는 서비스 이용을 마친 후 안전하게 로그아웃할 수 있다.
    - **`FR-U01.4` (계정 관리):** 부모는 '내 정보' 메뉴에서 자신의 비밀번호를 변경하거나 아이의 이름을 수정할 수 있다.
    - **`FR-U01.5` (로봇 등록):** 부모는 로봇 구매 시 제공되는 고유 시리얼 번호 또는 QR 코드를 통해, 자신의 계정에 **단 하나의 오리 로봇만**을 등록(연동)할 수 있다.
    - **`FR-U01.6` (로봇 상태 확인):** 부모는 웹/앱 메인 화면에서 웹 소켓 연결 상태 기반으로 내 로봇의 네트워크 연결 상태(예: 온라인, 오프라인)를 실시간으로 확인할 수 있다.
    - **`FR-U01.10` (회원 탈퇴):** 부모는 서비스 이용을 원치 않을 경우, 로봇 연동을 해제하고 회원 탈퇴를 통해 모든 정보를 삭제할 수 있다.
- **FR-U02: 부모 - 교감 및 성장 기록 확인 (기능 1 연계)**
    
    > 부모 사용자가 아이의 대화 내용을 바탕으로 생성된 리포트를 확인하는 기능입니다.
    > 
    - **`FR-U02.1` (스마트 리포트 알림):** 부모는 '스마트 리포트'(특이사항, 긍정 단어 감지 등)가 서버에서 자동으로 생성될 때마다 웹/앱을 통해 푸시 알림을 받을 수 있다.
    - **`FR-U02.2` (리포트 피드 조회):** 부모는 웹/앱의 리포트 메뉴에서, 생성된 '스마트 리포트'들을 최신순으로 모아볼 수 있다.
    - **`FR-U02.3` (리포트 상세 내용 확인):** 부모는 '스마트 리포트'를 선택하여, LLM이 요약한 '주요 대화 주제', '긍정 단어', '특이사항' 등 분석된 핵심 내용을 확인할 수 있다.
        
        ⇒ 구체적인 대화 수집 시나리오가 나오면 구체화할 예정
        
    - **`FR-U02.4` (원본 대화 확인):** 부모는 '스마트 리포트' 상세 화면 내에서, 요약의 근거가 된 '원본 대화' 텍스트를 (펼치기 기능 등을 통해) 함께 조회할 수 있다.
    - **`FR-U02.5` (일일 리포트 접근):** 부모는 '스마트 리포트' 피드와 별개로, 달력(캘린더) 형태의 UI를 통해 특정 과거 날짜를 선택할 수 있다.
    - **`FR-U02.6` (일일 리포트 조회):** 부모가 특정 날짜를 선택하면, 그날 하루 동안 포착된 모든 '핵심 대화' 기록(자발적 대화, 부모 질문&답변)을 시간순으로 조회할 수 있다.
    - **`FR-U02.7` (텍스트 전용 확인):** 부모는 아이의 프라이버시 보호를 위해, 텍스트로 변환된 '원본 대화'만 확인할 수 있으며, 원본 '음성 파일'을 직접 재생하거나 다운로드할 수는 없다.
- **FR-U03: 부모 - 스마트 안심 케어 (기능 2 연계)**
    
    > 부모 사용자가 오리 로봇의 카메라를 통해 아이의 상황을 실시간으로 확인하는 기능입니다.
    > 
    - **`FR-U03.1` (실시간 모니터링 시작):** 부모는 웹/앱의 메인 화면이나 전용 메뉴를 통해 '실시간 보기' 기능을 즉시 시작할 수 있다.
    - **`FR-U03.2` (실시간 영상 확인):** 부모는 '실시간 보기' 실행 시, 오리 로봇의 카메라를 통해 아이가 있는 환경의 영상을 실시간(낮은 지연 시간)으로 확인할 수 있다.
    - **`FR-U03.3` (실시간 음성 청취):** 부모는 '실시간 보기' 중, 영상과 함께 아이 주변의 소리(음성)도 실시간으로 들을 수 있다.
    - **`FR-U03.4` (음성 청취 제어):** 부모는 아이의 프라이버시나 상황에 따라, '실시간 보기' 중 음성 청취 기능(마이크)만 켜고 끌 수 있다.
        
        ⇒ 나이대를 고려했을때 사생활 존중에 대해서는 한번더 생각해볼 여지가 있는거 같음
        
        - GPT 의견
            
            > 1.  **아이 페르소나의 연령 변경 (7~11세):**
                가장 큰 이유입니다. 우리가 초기에 설정했던 `3~6세` 유아와 달리, `7~11세` 초등학생은 **자신만의 사생활(프라이버시)에 대한 민감도가 훨씬 높습니다.** 부모가 자신의 안전을 확인하는 것은 이해하더라도, 자신이 친구와 통화하거나 혼잣말을 하는 모든 소리를 항상 듣고 있다고 생각하면 큰 거부감을 느낄 수 있습니다.
            
            2.  **부모의 '안심' 목적 달성:**
                부모가 '실시간 보기'를 누르는 주된 이유는 '혹시 사고가 났나?', '아이가 방에 잘 있나?'와 같은 **시각적인 안전 확인**이 우선일 수 있습니다. 이 경우, 아이의 소리까지 강제로 듣게 하는 것보다, 부모가 "지금은 소리까지 들을 필요는 없겠다"라고 판단할 **선택권을 주는 것**이 서비스 만족도를 높일 수 있습니다.
            
            3.  **잠재적 불쾌감 해소:**
                부모가 아이의 모든 소리를 실시간으로 듣는 것이, 아이가 그 사실을 알게 되었을 때의 관계뿐만 아니라 부모 스스로에게도 '아이를 감시한다'는 죄책감이나 불쾌감을 줄 수 있습니다. 음성 청취를 선택적으로 만듦으로써 이러한 심리적 부담을 줄여줄 수 있습니다.
            
            이러한 이유로, 아이의 프라이버시를 존중하고 부모에게도 선택권을 주어 '안심'이라는 핵심 목적에만 집중할 수 있도록 '음성 청취 제어' 기능을 제안드렸습니다.
            > 
    - **`FR-U03.5` (자율 주행 확인):** 부모는 '실시간 보기' 중, 오리 로봇이 아이의 움직임을 자동으로 인식하여 따라다니는 모습(AI 객체 인식 및 자율 주행)을 확인할 수 있다.
    - **`FR-U03.6` (모니터링 종료):** 부모는 '실시간 보기'를 원할 때 언제든지 종료할 수 있다.
- **FR-U04: 부모 - 원격 소통 및 조작 (기능 3 연계)**
    
    > 부모 사용자가 오리 로봇을 통해 아이와 원격으로 소통하고, 로봇을 직접 조작하는 기능입니다.
    > 
    - **`FR-U04.1` (실시간 소통 시작):** 부모는 웹/앱에서 "라이브 톡" (Live Talk) 기능을 시작하여 로봇에 즉시 원격으로 접속할 수 있다.
    - **`FR-U04.2` (소통 시작 알림):** 부모가 '영상 통화'를 시작하면, 아이는 로봇의 알림음이나 LED 불빛을 통해 부모가 접속했음을 인지할 수 있다.
    - **`FR-U04.3` (실시간 영상/음성 수신):** 부모는 '영상 통화'가 연결된 동안, 아이의 모습과 목소리를 실시간으로 보고 들을 수 있다. ( `FR-U03`의 기능과 연계됨)
    - **`FR-U04.4` (텍스트 메시지 전송):** 부모는 '영상 통화' 화면의 전용 채팅창에 아이에게 전달할 메시지를 텍스트로 입력할 수 있다.
    - **`FR-U04.5` (TTS 음성 변환):** 부모가 텍스트를 입력하고 '전송' 버튼을 누르면, 로봇은 즉시 해당 내용을 오리의 친근한 캐릭터 목소리로 아이에게 말해준다.
    - **`FR-U04.6` (소통 종료):** 부모는 원할 때 언제든지 '영상 통화'를 종료하고 '오리 모드'로 복귀시킬 수 있다.
- **FR-U05: 아이 - 로봇과 상호작용**
    
    > 아이 사용자가 오리 로봇과 직접 소통하고 함께하며 정서적 교감을 나누는 기능입니다.
    > 
    - **`FR-U05.1` (자발적 대화):** 아이는 언제든지 오리 로봇에게 자유롭게 자신의 감정이나 이야기를 말할 수 있다 (로봇은 이를 '비밀 친구'로서 경청한다).
    - **`FR-U05.2` (질문/답변 소통):** 아이는 오리 로봇이 (부모로부터 받은) 질문을 오리의 목소리로 물어보면, 이에 대해 구두로 대답할 수 있다.
    - **`FR-U05.3` (물리적 동반):** 아이는 집 안에서 이동할 때, 오리 로봇이 자신을 인식하고 뒤따라오는 것을 경험할 수 있다.
    - **`FR-U05.5` (실시간 하이브리드 대화):** 아이는 '영상 통화' 중, 오리 로봇이 전달하는 부모의 메시지(TTS)를 듣고, 로봇의 카메라를 보며 자신의 목소리로 직접 대답할 수 있다.
    - **`FR-U05.6` (휴식 시간 인지):** 아이는 부모가 설정한 '방해 금지 시간대'에는 오리 로봇이 말을 걸거나 움직이지 않고 휴식 모드로 전환되는 것을 경험할 수 있다.
- **FR-U06: 아이 및 부모 - 로봇 스케줄링 ⇒ 시나리오에 맞춰 구체화할 예정**
    
    > 사용자가 경험하는 로봇의 일상적인 동작 모드(대기, 추적)와, 특정 이벤트 발생 시 로봇이 아이를 찾아가거나 알림을 주는 등 능동적으로 행동하는 방식에 대한 요구사항입니다. (세부 시나리오는 추후 구체화됩니다.)
    > 
    - **`FR-U06.1` (기본 동작 모드 - 동반):** 아이는 평상시('방해 금지 시간' 외)에, 로봇이 자신을 시각적으로 인식하고 따라다니는(`FR-U05.3` 연계) '동반 모드'를 기본으로 경험한다.
    - **`FR-U06.2` (기본 동작 모드 - 대기):** 아이가 시야에서 사라지거나 일정 시간 움직임이 없으면, 로봇은 지정된 대기 장소(예: 거실 중앙, 충전 스테이션 근처)로 이동하여 '대기 모드'로 전환된다.
    - **`FR-U06.3` (이벤트 - 부모 호출):** 부모가 '영상 통화'(`FR-U04.1`)나 '질문 메신저'(`FR-S02.10`)를 사용하고 아이가 로봇 근처에 없을 경우, 아이는 로봇이 자신을 **찾아와서**(예: "OO아, 엄마에게서 연락이 왔어!") 부모의 호출을 알리는 것을 경험한다.
    - **`FR-U06.4` (스케줄 준수 - 방해 금지):** 부모와 아이는, 부모가 설정한 '방해 금지 시간'(`FR-U01.9`)이 되면 로봇이 `FR-U06.1`, `FR-U06.3` 등의 모든 능동적인 움직임과 음성 알림을 중단하고 '조용한 대기 모드'를 유지하는 것을 인지한다.
    - **`FR-U06.5` (원격 소통 인지):** 아이는 오리 로봇의 알림(소리, LED 불빛 등)을 통해 부모가 '영상 통화'(부모 모드)를 시작했음을 인지할 수 있다.

### **2. 기능적 시스템 요구사항 (Functional System Requirements) - 최신화 버전**

> 사용자 요구사항을 만족시키기 위해 각 시스템 구성 요소가 제공해야 할 구체적인 기능 명세입니다.
> 
- **FR-S01: 웹 서비스 - 프론트엔드 (Frontend / Client-side)**
    
    > 부모 사용자가 직접 상호작용하는 웹/앱 인터페이스를 담당합니다. 서버로부터 받은 데이터를 시각화하고, 사용자의 입력을 서버로 전달하는 역할을 합니다.
    > 
    - **`FR-S01.1` (계정 UI):** 시스템은 이메일/비밀번호 기반의 회원가입, 로그인, 로그아웃, 비밀번호 변경, 회원 탈퇴 UI를 제공해야 한다. ( `FR-U01` 연계)
    - **`FR-S01.2` (계정 정보 UI):** 시스템은 부모가 등록된 단일 아동의 이름을 수정할 수 있는 '내 정보' UI를 제공해야 한다. ( `FR-U01.4` 연계)
    - **`FR-S01.3` (로봇 연동 UI):** 시스템은 부모가 QR 코드 스캔 또는 시리얼 번호 입력을 통해 단일 로봇을 계정에 등록하고, 연동을 해제할 수 있는 UI를 제공해야 한다. ( `FR-U01.5`, `FR-U01.10` 연계)
    - **`FR-S01.4` (로봇 설정 UI):** 시스템은 연동된 로봇의 '방해 금지 시간'을 설정할 수 있는 UI를 제공해야 한다. (**`FR-U05.6`**, **`FR-U06.4`** 연계)
    - **`FR-S01.5` (메인 대시보드):** 시스템은 로그인 시 로봇의 현재 연결 상태(온라인/오프라인)를 시각적으로 표시하는 메인 화면을 제공해야 한다. (**`FR-U01.6`** 연계)
    - **`FR-S01.6` (실시간 모니터링 UI):** 시스템은 '실시간 보기' 실행 시, 서버로부터 WebRTC 등의 프로토콜을 통해 영상 및 음성 스트림을 받아 지연 없이 재생하는 비디오 플레이어 컴포넌트를 구현해야 한다. ( `FR-U03.1`, `FR-U03.2`, `FR-U03.3` 연계)
    - **`FR-S01.7` (모니터링 제어 UI):** 시스템은 '실시간 보기' 화면 내에서, 수신되는 실시간 음성(마이크)을 켜고 끌 수 있는 음소거(Mute) 버튼을 제공해야 한다. ( `FR-U03.4` 연계)
    - **`FR-S01.8` (원격 소통 UI):** 시스템은 '영상 통화'(부모 모드) 실행 시, `FR-S01.6`의 비디오 플레이어와 텍스트 입력창, '전송' 버튼이 결합된 통합 UI를 제공해야 한다. ( `FR-U04.1`, `FR-U04.4` 연계)
    - **`FR-S01.9` (푸시 알림):** 시스템은 서버로부터 '스마트 리포트' 생성 알림을 받아, 사용자 기기에 푸시 알림(Notification)을 표시할 수 있어야 한다. ( `FR-U02.1` 연계)
    - **`FR-S01.10` (스마트 리포트 UI):** 시스템은 수신된 '스마트 리포트'를 최신순으로 보여주는 피드(Feed) 형태의 UI를 제공해야 한다. ( `FR-U02.2` 연계)
    - **`FR-S01.11` (리포트 상세 UI):** 시스템은 리포트 상세 화면에서 '요약', '특이사항' 및 '원본 대화 텍스트'(펼치기/접기 가능)를 시각적으로 명확하게 구분하여 제공해야 한다. ( `FR-U02.3`, `FR-U02.4` 연계)
    - **`FR-S01.12` (일일 리포트 UI):** 시스템은 사용자가 과거 날짜를 선택할 수 있는 달력(Calendar) UI와, 선택된 날짜의 모든 대화 기록을 시간순으로 조회할 수 있는 UI를 제공해야 한다. ( `FR-U02.5`, `FR-U02.6` 연계)
    - **`FR-S01.13` (음성 파일 접근 금지):** 시스템은 `FR-U02.7`에 의거, 리포트 조회 시 원본 음성 파일을 재생하거나 다운로드하는 기능을 일절 제공하지 않아야 한다.
    - **`FR-S01.14` (API 통신):** 시스템은 정의된 모든 기능(계정, 설정, 리포트 조회, 텍스트 전송 등)을 수행하기 위해 백엔드 서버(`FR-S02`)와 HTTP/WebSocket 기반의 API 통신을 수행해야 한다.
- **FR-S02: 웹 서비스 - 백엔드 (Backend / Server-side)**
    
    > 전체 서비스의 비즈니스 로직과 데이터 처리를 총괄하는 중앙 서버입니다. 프론트엔드, 로봇, AI 모델 사이의 모든 통신을 중계하고 관리합니다.
    > 
    
    > 
    > 
    - **(A) 계정 및 인증 (Account & Authentication)**
        - **`FR-S02.1` (계정 API):** 시스템은 프론트엔드(`FR-S01`)의 요청에 따라, 이메일/비밀번호 기반의 회원 가입, 로그인, 로그아웃, 회원 탈퇴 처리를 위한 API를 제공해야 한다.
        - **`FR-S02.2` (인증 토큰):** 시스템은 로그인 성공 시, 사용자 식별 및 인증을 위한 보안 토큰(예: JWT)을 발급해야 한다.
        - **`FR-S02.3` (정보 관리 API):** 시스템은 사용자가 자신의 비밀번호를 변경하거나, 등록된 아이의 이름을 수정하는 API를 제공해야 한다. (`FR-U01.4` 연계)
    - **(B) 로봇 관리 및 연동 (Robot Management)**
        - **`FR-S02.4` (로봇-사용자 매핑):** 시스템은 데이터베이스에 `User`와 `Robot`을 1:1로 매핑하여 관리해야 한다. (`FR-U01.5` 연계)
        - **`FR-S02.5` (로봇 연동 API):** 시스템은 프론트엔드로부터 로봇의 고유 식별자(시리얼/QR)를 받아 사용자 계정과 연동하고, 연동을 해제하는 API를 제공해야 한다.
        - **`FR-S02.6` (로봇 설정 API):** 시스템은 '방해 금지 시간' 등 설정값을 저장하고, 이를 로봇(`FR-S04`)으로 전송(Push)하거나 로봇이 조회(Pull)할 수 있도록 API를 제공해야 한다. (**`FR-U05.6`**, **`FR-U06.4`** 연계)
    - **(C) 실시간 통신 및 제어 (Real-time Communication)**
        - **`FR-S02.7` (로봇 소켓 서버):** 시스템은 로봇(`FR-S04`)과의 상시 연결을 위한 WebSocket 서버를 구현해야 한다.
        - **`FR-S02.8` (로봇 상태 관리):** 시스템은 `FR-S02.7`의 소켓 연결 상태를 기반으로 로봇의 온라인/오프라인 상태를 실시간으로 파악하고, 이를 프론트엔드(`FR-S01`)에 전달해야 한다. (**`FR-U01.6`** 연계)
        - **`FR-S02.9` (WebRTC 시그널링):** 시스템은 '실시간 보기' 및 '영상 통화' 시, 프론트엔드(`FR-S01`)와 로봇(`FR-S04`) 간의 WebRTC P2P 연결을 중계하기 위한 시그널링 서버(WebSocket 기반) 역할을 수행해야 한다. (`FR-U03`, `FR-U04` 연계)
        - **`FR-S02.10` (명령어 전송):** 시스템은 프론트엔드로부터 받은 텍스트 메시지(TTS 요청)나 '영상 통화' 시작/종료 신호를, `FR-S02.7`의 소켓을 통해 즉시 해당 로봇에게 전송해야 한다. (**`FR-U04.1`**, **`FR-U04.5`**, **`FR-U04.6`** 연계)
    - **(D) 데이터 처리 및 리포트 생성 (Data Processing & Reporting)**
        - **`FR-S02.11` (데이터베이스 스키마):** 시스템은 사용자, 로봇, 설정 정보 외에, 아이의 '핵심 대화'(원본 텍스트, 요약, 특이사항, 타임스탬프)를 저장하기 위한 데이터베이스 스키마를 설계해야 한다.
        - **`FR-S02.12` (음성 데이터 수신):** 시스템은 로봇(`FR-S04`)으로부터 전송된 아이의 '핵심 대화' 음성 세그먼트를 수신하는 엔드포인트를 제공해야 한다.
        - **`FR-S02.13` (AI 연동 로직):** 시스템은 `FR-S02.12`를 통해 음성 데이터를 수신하면, `FR-S05`(STT)를 호출하여 텍스트로 변환하고, 이 텍스트를 다시 `FR-S05`(LLM)에 전송하여 '요약', '긍정 단어', '특이사항' 등의 분석 결과를 받아와야 한다.
        - **`FR-S02.14` (리포트 저장):** 시스템은 `FR-S02.13`에서 가공된 분석 결과(요약, 원본 텍스트 등)를 `FR-S02.11`의 스키마에 맞춰 데이터베이스에 '스마트 리포트'로 저장해야 한다.
        - **`FR-S02.15` (음성 파일 파기):** 시스템은 `FR-U02.7`의 프라이버시 정책에 따라, `FR-S02.13`의 STT 변환이 완료된 후 원본 음성 파일을 즉시 파기해야 하며, 절대 데이터베이스에 저장하지 않아야 한다.
        - **`FR-S02.16` (리포트 조회 API):** 시스템은 프론트엔드에 '스마트 리포트' 피드(최신순)와 '일일 리포트'(날짜별)를 제공하는 API를 각각 제공해야 한다. (`FR-U02.2`, `FR-U02.6` 연계)
    - **(E) 알림 (Notification)**
        - **`FR-S02.17` (푸시 알림):** 시스템은 `FR-S02.14`에 따라 '스마트 리포트'가 생성될 때마다, 외부 푸시 알림 서비스(FCM, APN 등)와 연동하여 해당 사용자의 프론트엔드(`FR-S01`)로 알림을 전송해야 한다. (`FR-U02.1` 연계)
- **FR-S03: 오리 로봇 - 하드웨어 (Hardware)**
    
    > 아이와 물리적으로 상호작용하는 로봇의 모든 물리적 부품과 그 규격을 정의합니다.
    > 
    
    > 
    > 
    - **`FR-S03.1` (카메라):** 시스템은 실시간 영상 스트리밍(`FR-U03.2`) 및 AI 객체 인식(`FR-U03.5`)이 가능한 수준의 해상도(예: 720p 이상)와 저조도 성능을 갖춘 카메라 모듈을 탑재해야 한다.
    - **`FR-S03.2` (마이크 어레이):** 시스템은 아이의 목소리(`FR-U05.1`, `FR-U05.5`)를 명확하게 수음하고, 주변 소음 속에서도 음성을 식별할 수 있는 (단일 마이크 또는) 빔포밍이 가능한 마이크 어레이를 탑재해야 한다.
    - **`FR-S03.3` (스피커):** 시스템은 아이가 명확하게 인지할 수 있도록, 오리 캐릭터의 목소리(TTS)와 부모 모드 알림음을 충분한 음량으로 출력할 수 있는 스피커를 탑재해야 한다.
    - **`FR-S03.4` (구동계 - 모터 및 바퀴):** 시스템은 아이를 따라다니거나(`FR-U05.3`) 부모의 원격 조작에 응답할 수 있도록, 가정 내 일반적인 장애물(예: 얇은 매트, 문턱)을 통과할 수 있는 토크를 가진 모터와 바퀴(또는 캐터필러)를 갖추어야 한다.
    - **`FR-S03.5` (메인 프로세서):** 시스템은 카메라 영상 처리(객체 인식), 음성 데이터 실시간 인코딩, 서버 통신, 모터 제어 등을 동시에 수행할 수 있는 충분한 연산 능력을 갖춘 메인 프로세서(예: Raspberry Pi급 MCU/CPU)를 탑재해야 한다.
    - **`FR-S03.6` (통신 모듈):** 시스템은 고용량의 영상 및 음성 데이터를 백엔드 서버(`FR-S02`)와 안정적으로 실시간 송수신할 수 있도록 Wi-Fi(예: 802.11n 이상) 통신 모듈을 탑재해야 한다.
    - **`FR-S03.7` (배터리 및 전원부):** 시스템은 아이의 주 활동 시간 동안(예: 최소 N시간 이상) 지속적으로 동작할 수 있는 용량의 배터리와, 충전 상태를 관리할 수 있는 전원 관리 시스템(PMS)을 갖추어야 한다.
    - **`FR-S03.8` (센서 - 장애물 감지):** 시스템은 자율 주행 시 가구나 벽에 부딪히지 않도록, 전방 및 주변의 장애물을 감지할 수 있는 센서(예: IR 센서, ToF 센서 등)를 탑재해야 한다.
    - **`FR-S03.9` (LED 및 상태 표시등):** 시스템은 로봇의 현재 상태(예: 전원 켜짐, 부모 모드 접속, 배터리 부족)를 아이나 부모가 시각적으로 인지할 수 있도록 다색 LED 표시등을 탑재해야 한다. (`FR-U04.2` 연계)
- **FR-S04: 오리 로봇 - 제어 소프트웨어 (Embedded / Control S/W)**
    
    > 로봇 하드웨어 상에서 직접 동작하며, 하드웨어를 제어하고 서버와 통신하는 임베디드 소프트웨어입니다.
    > 
    
    > 
    > 
    - **(A) 시스템 및 하드웨어 제어 (System & H/W Control)**
        - **`FR-S04.1` (시스템 부팅 및 초기화):** 시스템은 전원 인가 시, 임베디드 운영체제(예: Linux, RTOS)를 부팅하고 카메라, 마이크, 스피커, 모터, 센서 등 모든 하드웨어(`FR-S03`) 드라이버를 초기화해야 한다.
        - **`FR-S04.2` (하드웨어 제어 API):** 시스템은 스피커 볼륨 조절, LED 상태 변경, 모터 구동 등 하드웨어의 모든 기능을 제어할 수 있는 내부 API를 제공해야 한다.
        - **`FR-S04.3` (상태 관리):** 시스템은 '대기 모드', '추적 모드', '부모 모드', '충전 중', '방해 금지 모드' 등 로봇의 현재 상태를 명확히 정의하고 관리해야 한다. (`FR-U05.6` 연계)
    - **(B) 네트워크 및 서버 통신 (Network & Server Comms)**
        - **`FR-S04.4` (Wi-Fi 연결 관리):** 시스템은 부팅 시 저장된 Wi-Fi 정보로 자동 접속을 시도하고, 연결이 끊겼을 경우 재접속을 시도해야 한다. (`FR-S03.6` 연계)
        - **`FR-S04.5` (백엔드 소켓 연결):** 시스템은 Wi-Fi 연결 성공 시, 백엔드 서버(`FR-S02.7`)의 WebSocket에 접속하여 상시 연결(Persistent Connection)을 수립하고 유지해야 한다 (예: Heartbeat 전송).
        - **`FR-S04.6` (서버 명령 수신 및 처리):** 시스템은 `FR-S04.5`의 소켓을 통해 백엔드로부터 전송되는 명령(예: '영상 통화 시작', 'TTS 재생', **'방해 금지 시간' 설정 변경**)을 실시간으로 수신하고 파싱하여 처리해야 한다. (`FR-U04` 연계)
    - **(C) 데이터 수집 및 스트리밍 (Data Acquisition & Streaming)**
        - **`FR-S04.7` (실시간 영상/음성 스트리밍):** 시스템은 '부모 모드' 시작 명령을 수신하면, 카메라(`FR-S03.1`)와 마이크(`FR-S03.2`)의 데이터를 실시간으로 인코딩하여, WebRTC 프로토콜을 통해 백엔드 시그널링 서버(`FR-S02.9`)를 경유, 프론트엔드(`FR-S01`)로 스트리밍해야 한다.
        - **`FR-S04.8` (핵심 대화 감지 및 전송):** 시스템은 평시(오리 모드)에 마이크를 통해 음성을 감지(VAD - Voice Activity Detection)하고, 아이의 발화로 판단되는 '의미 있는 음성 세그먼트'를 포착해야 한다.
        - **`FR-S04.9` (음성 데이터 전송):** 시스템은 `FR-S04.8`에서 포착된 음성 세그먼트를 백엔드 서버의 음성 데이터 수신 엔드포인트(`FR-S02.12`)로 전송하여 STT 및 분석을 요청해야 한다. (`FR-U02` 연계)
    - **(D) AI 및 자율 주행 (AI & Autonomous Driving)**
        - **`FR-S04.10` (객체 인식 및 추적):** 시스템은 카메라 영상을 실시간으로 분석하여, 등록된 '아이' 객체를 탐지(AI 모델 `FR-S05` 활용)하고, 아이의 위치를 지속적으로 추적해야 한다. (`FR-U03.5`, `FR-U05.3` 연계)
        - **`FR-S04.11` (장애물 감지):** 시스템은 주행 중 장애물 감지 센서(`FR-S03.8`)로부터 데이터를 실시간으로 수신하여 전방 및 측면의 장애물을 인지해야 한다.
        - **`FR-S04.12` (자율 주행 로직):** 시스템은 `FR-S04.10`(아이 위치)과 `FR-S04.11`(장애물 위치) 정보를 통합하여, 아이와 일정한 거리를 유지하며 충돌 없이 따라갈 수 있도록 모터(`FR-S03.4`)의 속도와 방향을 제어해야 한다.
    - **(E) 사용자 상호작용 (User Interaction)**
        - **`FR-S04.13` (TTS 엔진 연동):** 시스템은 백엔드로부터 텍스트(TTS 요청)를 수신하면, 이를 음성으로 변환(로컬 엔진 또는 클라우드 API 연동)하여 스피커(`FR-S03.3`)로 출력해야 한다. (`FR-U04.5`, `FR-U05.2` 연계)
        - **`FR-S04.14` (상태 표시):** 시스템은 `FR-S04.3`의 현재 상태에 따라, LED(`FR-S03.9`)의 색상이나 점멸 패턴을 변경하여 사용자에게 시각적인 피드백을 제공해야 한다. (예: 부모 모드 접속 시 - 초록색 점등) (`FR-U04.2` 연계)
- **FR-S05: 상용 AI 활용 및 프롬프트 엔지니어링 (Commercial AI Utilization & Prompt Engineering)**
    
    > 서비스의 핵심 지능을 구현하기 위해, 어떤 상용 AI 모델(API)을 선택하고, 이 모델들에게 어떤 지시(프롬프트)를 내릴지 정의하는 영역입니다.
    > 
    
    > 
    > 
    - **(A) AI 모델 선정 (Model Selection)**
        - **`FR-S05.1` (STT 모델):** 시스템은 로봇(`FR-S04.9`)으로부터 수신된 한국어 아동의 음성 세그먼트를 높은 정확도로 텍스트 변환할 수 있는 상용 STT API를 선정하고 명세화해야 한다. (아동 발음/어휘에 대한 강건성 고려)
        - **`FR-S05.2` (LLM 모델):** 시스템은 STT로 변환된 한국어 텍스트의 맥락을 이해하고, '요약', '키워드 추출', '특이사항 감지' 등 복합적인 작업을 수행할 수 있는 고성능/저비용의 상용 LLM API를 선정해야 한다.
        - **`FR-S05.3` (TTS 모델):** 시스템은 부모가 입력한 한국어 텍스트를, 아이에게 친근감과 안정감을 줄 수 있는 '오리 캐릭터' 톤의 음성으로 변환할 수 있는 상용 TTS API를 선정해야 한다. (`FR-U04.5` 연계)
        - **`FR-S05.4` (객체 탐지 모델):** 시스템은 로봇의 카메라 영상에서 '사람'(아이)을 실시간으로 탐지할 수 있는, 로봇 하드웨어(`FR-S03.5`)에 탑재 가능한(Edge) 경량화된 객체 탐지(Object Detection) 모델(예: pre-trained YOLO, MobileNet 등)을 선정해야 한다.
    - **(B) 프롬프트 엔지니어링 (Prompt Engineering)**
        - **`FR-S05.5` (리포트 분석 프롬프트):** 시스템은 `FR-S05.2`의 LLM이 `FR-U02`의 요구사항을 정확히 수행하도록, 다음과 같은 역할을 하는 프롬프트 템플릿을 설계, 테스트 및 버전 관리해야 한다:
            - `FR-S05.5.1` (주제 요약): 입력된 대화 텍스트의 핵심 주제를 1~2 문장으로 요약하는 프롬프트.
            - `FR-S05.5.2` (긍정 단어 추출): 아이가 사용한 긍정적/기쁨의 어휘를 식별하는 프롬프트.
            - `FR-S05.5.3` (특이사항 감지): '가족 언급', '강한 감정 표현(슬픔, 화남)', '반복적 요청' 등 부모가 알아야 할 특이사항을 식별하는 프롬프트.
        - **`FR-S05.6` (응답 포맷 정의):** 시스템은 `FR-S05.5`의 모든 프롬프트에, 백엔드(`FR-S02.13`)가 쉽게 파싱할 수 있도록 **반드시 JSON 형식**으로 응답을 반환하라는 지시(Instruction)를 포함해야 한다.
            - *(예시: {"summary": "...", "positive_keywords": [...], "special_notes": [...]})*
    - **(C) AI 모델 기능 구현 (AI Model Implementation)**
        - **`FR-S05.7` (객체 탐지 구현):** 시스템은 `FR-S05.4`에서 선정된 모델을 로봇 제어 소프트웨어(`FR-S04`) 내에 이식(Porting)하고, 카메라 영상 프레임마다 '아이'의 위치 좌표(Bounding Box)를 반환하는 기능을 구현해야 한다. (이는 `FR-S04.10`의 세부 구현 사항임)
- **FR-S06: AI 서비스 운영 및 최적화 (AI Service Operation & Optimization)**
    
    > 상용 AI API를 안정적이고 비용 효율적으로 사용하기 위한 모든 운영, 관리, 최적화 시스템을 정의합니다.
    > 
    
    > 
    > 
    - **(A) 연동 및 보안 (Interface & Security)**
        - **`FR-S06.1` (API 인터페이스):** 시스템은 백엔드(`FR-S02`)가 다양한 AI 서비스(STT, LLM, TTS)를 일관된 방식으로 호출할 수 있도록, 공통 인터페이스 모듈(Wrapper/Adapter)을 구현해야 한다.
        - **`FR-S06.2` (API 키 관리):** 시스템은 모든 외부 서비스의 API 키를 코드베이스에서 분리하여, 환경 변수 또는 전용 Secret Manager를 통해 암호화하여 안전하게 저장 및 관리해야 한다.
    - **(B) 비용 최적화 (Cost Optimization)**
        - **`FR-S06.3` (토큰 계산):** 시스템은 `FR-S05.2`의 LLM API를 호출할 때마다, 전송된 프롬프트(입력)와 수신된 응답(출력)의 토큰 수를 정확하게 계산해야 한다.
        - **`FR-S06.4` (토큰 사용량 최적화):** 시스템(백엔드 로직)은 LLM에 불필요한 맥락이나 반복적인 지시어를 제거하여, 입력 프롬프트의 길이를 최소화하고 토큰 사용량을 최적화해야 한다.
        - **`FR-S06.5` (응답 캐싱):** 시스템은 이전에 동일한 내용(예: 부모의 동일한 질문, 아이의 동일한 혼잣말)으로 LLM에 요청한 이력이 있는 경우, API를 재호출하지 않고 캐시(Cache, 예: Redis)된 응답을 즉시 반환해야 한다.
        - **`FR-S06.6` (캐시 무효화):** 시스템은 `FR-S06.5`의 캐시 데이터가 무기한 저장되지 않도록, 적절한 만료 시간(TTL, Time-to-Live)을 설정하여 데이터의 정합성을 관리해야 한다.
    - **(C) 모니터링 및 로깅 (Monitoring & Logging)**
        - **`FR-S06.7` (API 호출 로깅):** 시스템은 모든 외부 AI API 호출에 대해, 호출 시간, 응답 시간(Latency), 성공/실패 여부, HTTP 상태 코드, 그리고 `FR-S06.3`에서 계산된 토큰 사용량을 상세히 로깅해야 한다.
        - **`FR-S06.8` (비용 모니터링):** 시스템은 `FR-S06.7`의 로그를 기반으로, API 서비스별 일별/월별 누적 토큰 사용량과 예상 비용을 집계할 수 있어야 한다.
        - **`FR-S06.9` (이상 비용 감지):** 시스템은 API 사용량이 사전에 설정된 임계값을 초과할 경우(예: 일일 $100 초과), 즉시 운영 관리자에게 알림(예: Slack, 이메일)을 발송하는 모니터링 기능을 갖추어야 한다.
    - **(D) 안정성 및 오류 처리 (Stability & Error Handling)**
        - **`FR-S06.10` (오류 처리):** 시스템은 외부 API 호출 시 발생하는 HTTP 오류 코드(4xx: 클라이언트 오류, 5xx: 서버 오류)를 명확하게 감지하고 처리해야 한다.
        - **`FR-S06.11` (자동 재시도 로직):** 시스템은 API의 일시적인 서버 오류(5xx)나 속도 제한(429 Rate Limit) 발생 시, 서비스가 중단되지 않도록 **'Exponential Backoff'** 정책(시도 간격을 점차 늘려가며 재시도)에 따른 자동 재시도 로직을 구현해야 한다.
        - **`FR-S06.12` (Fallback 응답):** 시스템은 `FR-S06.11`의 재시도에도 불구하고 최종적으로 API 호출에 실패했을 때, 사용자나 백엔드 로직이 무한 대기하지 않도록, 미리 정의된 기본 응답(Fallback)을 반환하거나 명확한 오류를 리턴해야 한다.
